# 실험 6 LOSO — 장면에서 매칭 임계값을 예측할 수 있는가 (**사전 선언**)

> **이 문서는 자료를 보기 전에 커밋한다.** `headroom.py` 의 결과([A] 여유 없음,
> [B] 최적이 장면마다 갈림)는 이미 알고 있고 **그것이 이 실험을 낳았다.**
> `predictors.py` 의 상관표도 봤다 — 그래서 **예측변수를 사람이 고르지 않는다**
> (아래 「fold 안 선택」). LOSO 의 숫자는 하나도 안 봤다.

## 무엇이 미결인가

`headroom.py` 가 둘을 보였다.

| | 결과 | 뜻 |
|---|---|---|
| **[A]** | 전역 최적 0.85 는 기본 0.80 대비 **+0.037** | 전역 여유 **없음**. ByteTrack 기본값이 이미 최적 |
| **[B]** | 시퀀스별 최적이 0.70~0.95 로 갈림, 신탁 이득 평균 **+1.07** | 이득은 **전부** "장면마다 다르다" 에 있다 |

**[B] 의 +1.07 은 신탁이다.** held-out 시퀀스의 정답을 보고 고른 값이므로
도달 불가능한 상한이다. 남은 질문은 하나다:

> **장면을 보고(GT 없이) 임계값을 고르면, 본 적 없는 장면에서 기본값 0.80 을 이기는가.**

## 왜 이 자리인가 — 이 연구의 논지와 맞물린다

임계값은 **장면당 스칼라 하나**다. 절대 눈금이 필요 없고 **단조 관계만** 있으면 된다.
그게 실험 1 이 확정한 σ 의 성질이다 — **신호 O**(편상관 0.32, 검출기·해상도 무관),
**눈금 X**(χ² 80~562배). 지금까지 우리는 눈금이 필요한 자리(거리 exp05, 칼만 R exp02,
상자 확장 exp03)에 눈금이 틀린 양을 넣어 전부 졌다.

**여기가 눈금이 필요 없는 첫 자리다.** 그래서 σ 계열 관측량이 후보에 들어 있고,
그것이 선택되는지 자체가 종말점 하나다([4]).

## 라벨 — 시퀀스별 최적 임계값

그리드를 재생하고 시퀀스별 HOTA 의 argmax 를 라벨로 쓴다.

```
GRID = [0.5, 0.6, 0.7, 0.75, 0.8, 0.85, 0.9, 0.95, 0.98]
```

**0.98 을 추가한다.** `headroom.py` 의 그리드는 0.95 가 상단이었는데
**MOT17-10 과 -13 의 최적이 그 경계에 붙었다.** 경계에 붙은 argmax 는 라벨로 쓸 수
없다 — 진짜 최적이 밖에 있을 수 있다. 하단 0.70(MOT17-11)은 내부이므로 건드리지 않는다.

> **0.98 을 넣으면 라벨이 바뀔 수 있다.** 바뀌면 바뀐 대로 보고하고,
> `predictors.py` 에 하드코딩된 `BEST`/`GAIN` 도 함께 정정한다.

## 갈래 넷 — **R1 이 진짜 비교 대상이다**

각 fold 에서 6개 시퀀스로 정하고, 본 적 없는 1개에 적용해 HOTA 를 잰다.

| 갈래 | 임계값을 어떻게 정하는가 | 장면 정보 |
|---|---|---|
| **R0** | **0.80 고정** (ByteTrack 기본값) | 없음 |
| **R1** | 훈련 6개 최적값의 **중앙값** | **없음** |
| **R2** | 훈련 6개로 적합한 **예측 규칙** | 있음 |
| **R3** | held-out 자신의 argmax (**신탁**) | 정답을 봄 |

**R1 을 빼면 이 실험은 무효다.** 실험 1e 에서 검출별 정보가 **0** 인 상수 Σ 가
NLL 최고를 찍은 적이 있다. 같은 함정이 여기 있다 — 이득이 "장면을 봐서" 가 아니라
"0.80 이라는 숫자가 나빠서" 일 수 있다. R1 은 장면을 전혀 안 보고 눈금만 옮긴다.

## 규칙 형태 — 중앙값 이분. **n=6 이므로 이보다 복잡하면 안 된다**

훈련 6개를 예측변수 `x` 의 중앙값으로 둘로 가르고, 각 쪽 라벨의 중앙값을 그 쪽의
예측값으로 쓴다. held-out 은 자기 `x` 가 훈련 중앙값보다 크면 상위 쪽 값을 받는다.

```
lo = median{ best_i : x_i <= median(x_train) }
hi = median{ best_i : x_i >  median(x_train) }
pred(x*) = hi if x* > median(x_train) else lo
```

중앙값이 그리드 위에 없으면(예: 0.875) **가장 가까운 그리드 값으로 스냅**하고,
동률이면 **작은 쪽**을 쓴다(보수적). R1 도 같은 스냅 규칙을 쓴다.

회귀나 다변량은 쓰지 않는다. **6점에 계수 두 개면 이미 과적합이다.**

## fold 안 선택 — 예측변수를 사람이 고르지 않는다

`predictors.py` 의 상관표를 이미 봤으므로 **거기서 최고를 골라 쓰면 그건 결과가
아니라 자료 재사용이다.** 대신 각 fold 에서 **훈련 6개만으로** 후보별
|스피어만 ρ(x, best)| 를 재고 최대인 것을 고른다. 동률이면 아래 목록의 앞선 것.

후보 9개 (`predictors.py:scene_stats`, **GT 를 안 쓴다**):

1. 밀도 (프레임당 고신뢰 검출 수)
2. 겹침 (평균 최대 IoU)
3. 자차운동 (프레임 간 중앙 중심 이동 px)
4. 상자 높이 중앙값
5. 높이 산포 CV
6. **σ 중앙값 (px)**
7. **σ/√area 중앙값**
8. **σ 산포 CV**
9. 점수 중앙값

**6~8 이 σ 계열이다.** 이 목록은 여기서 고정하고 늘리지 않는다.

## 사전 선언한 판정

집계는 두 가지를 **둘 다** 보고한다 — 검출 수 가중 결합 HOTA(TrackEval 표준)와
가중 없는 시퀀스 평균. **주 판정은 가중 결합**(exp05 와 같은 자).

| # | 종말점 | 묻는 것 |
|---|---|---|
| **[1]** | **R2 − R0** | **주 종말점.** 규칙이 기본값을 이기는가 |
| **[2]** | **R2 − R1** | **기여 귀속.** 장면을 본 것이 상수보다 나은가 |
| [3] | R3 − R0 | 신탁 상한 (참고. 주장 아님) |
| [4] | 선택된 예측변수가 **σ 계열(6~8)인 fold 수** | σ 가 눈금 없는 자리에서 쓸모 있는가 |

판정폭은 **0.3 HOTA.** exp03·exp05·exp06[A] 와 같은 자를 쓴다.

### 읽는 법 — **미리 못박는다**

| [1] | [2] | 결론 |
|---|---|---|
| `> +0.3` | `> +0.3` | **적응 규칙이 실재한다.** 다음은 외부 데이터셋 검증 (MOT20/DanceTrack/KITTI) |
| `> +0.3` | `<= +0.3` | **상수만 바꾸면 된다.** 장면 관측량의 기여는 0. 남는 건 "0.80 이 최적이 아니다" 뿐이고 그건 **튜닝이지 연구가 아니다** |
| `-0.3 ~ +0.3` | — | **레버 2 가 죽는다.** 신탁 +1.07 은 도달 불가였다. 임계값 통로도 닫힌다 |
| `< -0.3` | — | 같은 결론, 더 강하게. **규칙이 해롭다** |

**[4] 는 [1] 과 독립으로 읽는다.** σ 계열이 뽑혔는데 [1] 이 실패하면
"σ 는 골라지지만 도움이 안 된다"이고, σ 계열이 안 뽑히면
"눈금이 필요 없는 자리에서도 σ 는 밀도·겹침에 진다"이다. **후자가 더 무겁다.**

## 관문 [0] — 배관 검산. 안 맞으면 판정하지 않는다

재생성한 per-seq HOTA 표를 **기존 8개 격자에 한정**해서 `predictors.py` 의
하드코딩 `BEST` 와 대조한다. **7/7 일치해야 한다.** (0.98 은 새 값이므로
이 대조에서 제외한다.) 안 맞으면 재생 경로가 틀린 것이므로 **거기서 멈춘다.**

실험 5 에서 얻은 교훈이다 — 같은 양을 다른 경로로 한 번 더 재라.

## 함정 — 결과 보기 전에 적는다

**(a) 라벨의 절반 이상이 잡음이다.** `headroom.py` 의 신탁 이득은
MOT17-09 0.20 / 04 0.35 / 02 0.46 / 05 0.55 / 10 0.65 로 **7개 중 5개가
판정폭 0.3 근처이거나 아래다.** 그 시퀀스들의 argmax 는 사실상 평평한 곡선 위의
잡음이다. 즉 **라벨 자체가 약하다.** 이 실험은 검정력이 낮다.
그래도 한다 — 잡음 라벨로도 [1] 이 통과하면 그건 진짜다.

**(b) 선택 안정성을 기록한다.** 7 fold 에서 어느 예측변수가 뽑히는지 세어
보고한다. 매번 다르면 규칙이 불안정하다는 직접 증거다.

**(c) n=7 이다.** 부호검정을 함께 보고하되 **판정은 효과 크기(0.3)로 한다.**
7/7 이어야 겨우 p=0.016 이다.

**(d) argmax 는 그리드 위에서만 정의된다.** 그리드 밖이나 격자 사이의 최적은
못 본다. 0.98 추가는 상단 경계 문제만 고치고 이 한계는 남는다.

## 이 실험이 답하지 않는 것

- **MOT17 val_half 7시퀀스뿐이다.** 표본 문제는 그대로다
- **1회 실행.** 시드 변동폭을 안 쟀다. 판정폭 미만은 주장하지 않는다
- **검출은 캐시 고정**(`data/exp05/*.npz`, 실험 5 와 비트 단위 동일).
  검출기 쪽 변화는 이 실험에 없다
- **2단계 임계값(0.5 하드코딩)은 안 건드린다.** 움직이는 것은 `match_thresh` 하나
- **규칙이 이겨도 그건 MOT17 안에서다.** 외부 검증 없이 일반화하지 않는다
