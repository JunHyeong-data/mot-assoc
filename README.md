# mot-assoc

다중객체추적(MOT)의 데이터 연관에서, **검출 신뢰도가 비용에 도달하는 조건**을 확인한다.

박준형 · 인하대학교 데이터사이언스학과

---

## 질문

트래킹은 매 프레임 검출을 기존 트랙에 짝지어 붙인다. 그 짝짓기는 비용행렬
(트랙 M × 검출 N)을 만들고 헝가리안으로 푸는 방식이 표준이다.

그 비용에 **검출이 얼마나 믿을 만한지**는 부분적으로만 들어간다. 정확히 하면:

- **분류 신뢰도(score)는 이미 들어간다.** ByteTrack의 `fuse_score`가
  `cost = 1 − IoU_ij · s_j` 로 곱해 넣고, ultralytics 기본값이 `True`다.
  "신뢰도가 비용에 안 들어간다"는 서술은 사실이 아니다. 쓰면 안 된다.
- **위치 불확실성(공분산)은 안 들어간다.** SORT는 IoU 하나,
  DeepSORT는 마할라노비스 + 외형인데 검출 쪽 공분산은 상수로 고정된다.

score는 "이 상자에 사람이 있는가"이고, 이 연구가 묻는 것은
"이 상자가 어디 있는지를 얼마나 아는가"다. 후자가 비어 있다.

> 검출별 **위치** 불확실성을 비용에 넣으면 짝짓기가 달라지는가?
> 달라진다면 어떤 조건에서인가?

## 어디서 나온 질문인가

야간 사각지대 경보 시스템(BSDsystem-Deepnight)을 만들면서, 경보 판정이
전적으로 트랙 연속성에 의존한다는 걸 알게 됐다. 그런데 매칭 비용을 직접
짜보니 IoU 하나뿐이었다.

## 현재 상태

| 항목 | 지위 |
|---|---|
| 헝가리안은 행상수를 더해도 불변 — **단 M ≤ N 일 때만** | **증명** |
| 헝가리안은 열상수를 더해도 불변 — **단 M ≥ N 일 때만** | **증명** |
| 검출 공분산이 모두 같으면 공분산항이 순수 행상수 → **M ≤ N 이면** 기여 0 | **증명 + 합성 수치 확인** |
| **M > N 이면 상수 공분산이어도 할당이 바뀐다** (합성 20×10 에서 93/100) | **합성 수치 관찰** |
| 개체별 공분산이면 할당이 바뀐다 (합성 91/100) | **합성 수치 관찰** |
| 가림이 길수록 이중중심화 잔차 감소 (\|R\|_mean 0.342 → 0.003, 136배) | **합성 수치 관찰** |
| **매칭 임계값이 붙으면 불변성이 M, N 과 무관하게 깨진다** (10×15에서 467/500) | **합성 수치 관찰** |
| 신뢰도를 **더하기**로 넣으면 잔차 기여가 0 (2e-16). 곱해야 도달한다 | **증명 + 합성 수치 확인** |
| ByteTrack `fuse_score`가 score를 곱으로 이미 넣고 있다 (기본값 True) | **소스 확인** |
| ultralytics ByteTrack/BoT-SORT에는 마할라노비스 게이팅이 없다 | **소스 확인** |
| 기본 설정에서 M > N 이 지배적 (주행영상 1단계 77.2%) — **단 `track_buffer` 의존** | **실측** |
| 최적쌍의 19.7%가 임계값에서 잘린다 (주행영상 1단계) | **실측** |
| 행상수를 더하면 실제 매칭이 바뀐다 (쌍 단위 8.9~24.9%, 영상 4편 전부) | **실측** |
| ~~밀도가 올라가면 민감도가 커진다~~ — 같은 M=33에서 24.9% vs 12.9%로 갈림 | **철회** |
| **그 민감도는 `track_buffer` 와 무관하다** (1~120에서 24.8~29.1%) → 원인은 임계값 | **실측** |
| ByteTrack 2단계가 기본 설정에서 매칭 불가능하다 (`fuse_score` 끄면 0→279건) | **증명 + 실측** |
| **칼만 측정잡음 R이 트랙 높이에서 나온다 → 검출 쪽 통로가 구조적으로 없다** | **소스 확인** |
| 바타차야는 통로를 열지만, 로그행렬식 항 중 `0.5 ln\|(Σt+Σd)/2\|` 하나뿐이다 | **증명 + 합성 확인** |
| 그 통로는 Σt ≫ Σd (긴 가림) 에서 닫힌다. 순진한 마할라노비스 개조는 0%로 죽는다 | **합성 수치 관찰** |
| ~~NMS 후보 분산이 위치오차의 대리변수다~~ — 상자크기 모형에도 진다 | **기각 — 실험 1** |
| 가림에서 잔차 SNR이 3.65 → 0.06 으로 붕괴한다 (배율이 아닌 정보 소멸) | **합성 수치 관찰** |
| 행 단위 정규화(z·순위)는 그것을 되살리지 못한다. 오히려 나빠진다 | **합성 수치 관찰** |
| MOT17급 보행자 밀집에서도 위 실측이 같은 방향인가 | **미검증** |
| 실데이터(MOT17)에서 위 성질이 유지되는가 | **미검증** |
| 트래킹 성능이 실제로 오르는가 | **미검증** |

**두 개의 큰 단서 조항.**

1. M > N 은 가림으로 검출이 줄어드는 상황이다. 이 연구가 겨냥하는 바로 그 구간에서
   "분리되면 기여 0" 전제가 성립하지 않는다. 실데이터에서 M, N 분포를 먼저 세야 한다.
2. 더 근본적으로, **"분리되면 기여 0" 은 임계값 없는 순수 헝가리안에서만 참이다.**
   실제 트래커는 항상 `match_thresh` 로 자른다. 임계값이 있으면 행상수도
   채택 여부를 바꾼다. 이론적 뼈대를 임계값 포함 형태로 다시 세워야 한다.

여기서 나오는 설계 제약: 검출 불확실성을 스칼라로 **더하는** 형태는 원리적으로
쓸 수 없다 (순수 열/행상수). 트랙과 상호작용하는 형태여야 한다.
단, 임계값 경로로는 여전히 결과가 바뀌므로 **"성능이 올랐다"를 "정보가 전달됐다"의
근거로 쓰면 안 된다.** 두 경로를 분리해서 보고할 것.

**모든 수치는 현재 합성 실험이다.** 실데이터 검증 전에는 그렇게만 말한다.
