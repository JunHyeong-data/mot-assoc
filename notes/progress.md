### 8·9번이 어떻게 잡혔나 — exp04 와 곱셈이 안 맞았다

`run_sequence.py` 가 letterbox→원본 배율을 **NMS 가로채기 안에서** 쟀는데,
ultralytics 는 NMS 가 돌아온 **뒤에** `scale_boxes` 를 건다. 그래서 배율이

결정적인 것은 **exp04 가 같은 양을 이미 제대로 쟀다는 점**이다. exp04 는
"저자 σ 는 우리 σ 의 1/3" 이라 쟀고, 그렇다면 z² 은 **9배** 차이나야 한다.
그런데 exp01 의 옛 수치는 663/594 = **1.1배** 였다. **정면으로 모순인데
아무도 대조해 보지 않았다.** 고친 수치는 562/80 = 7.0배로 맞는다.

> **교훈 셋째: 실험이 겹치는 자리는 곱셈으로 대조하라.**
> 두 실험이 같은 양을 다르게 말하면 둘 중 하나가 틀린 것이다.

### 가장 값진 순간

**exp04 를 하다가 exp01 의 버그를 잡았다.** "포크 분산이랑 우리 분산 대조해줘"
때문에 같은 가로채기를 새로 짰고, `E[w] = 1010 px` 가 나왔다. 보행자 폭이
1010 px 일 리 없다. **그 대조를 안 했으면 잘못된 기각이 논문에 들어갔을 것이다.**

교훈은 둘이다.
1. **같은 양을 다른 경로로 한 번 더 재라.**
2. **단위와 크기의 상식 검사가 조용한 버그를 잡는다.**

### MOT17-05 를 갈랐다 — 네 번째 제약이 나왔다

7개 중 유일한 640×480 인데 두 설정 모두에서 χ² 배율이 혼자 튀었다

| MOT17-05 @640 | **1.000** | **649배** | 0.00092 |
| MOT17-05 @1920 | 0.333 | **83배** | 0.00745 |

  **649 → 83배**로 정상 범위에 들어온다

### 실험 1e — **보정한 뒤 넣기.** coverage 통과, 크기모형 못 이김

7시퀀스 leave-one-sequence-out (6개로 적합, 본 적 없는 1개로 평가).

- **주 종말점 coverage 통과** — E1 컨포멀 **96.1%** (목표 95%, 날것은 10.5%).
  **보정은 장면을 넘어간다**
- **진짜 관문 실패** — NLL 에서 E 최선 7.18 vs **C(상자크기) 6.05**.
  사전 선언의 두 번째 행: **눈금은 고쳐지지만 모양은 여전히 틀렸다**

**왜 못 고치는지를 찾았다 (탐색적).** 보정 뒤 z² 중앙값/χ² 중앙값이 모든 모형에서
**0.04~0.34** 다 (1.0 이어야 함). 95% 꼬리를 맞추면 가운데가 통째로 과대해진다.
원인은 분포 모양이다 — **꼬리비**(99%분위배율÷50%분위배율)가 가우시안이면 1.0 인데
실측 **12~213** 이다.

> **문제는 "σ 의 눈금이 틀렸다" 가 아니라 "2×2 가우시안 공분산이라는 대상 자체가
> 틀렸다" 이다.** UncertaintyTrack 이 "가우시안 가정과 안 맞는 듯" 이라 **추측**한
> 자리에 이제 숫자가 둘이다 — 눈금 24배, 꼬리비 12~213배.

정직하게: 컨포멀의 이득은 작다 (E1 96.1%/7.43 vs 단순 전역상수배 A1 97.0%/7.64).
그리고 **검출별 정보가 0 인 B(상수 Σ)가 NLL 최고(5.78)** 다. 둘 다 같은 말을 한다.

### 실험 1f — Student-t. **꼬리가 원인이 아니었다. 0/7**

1e 가 지목한 꼬리를 담는 분포족을 줬다. **핵심 설계는 t 를 모든 모형에 똑같이
주는 것** — A 에만 주면 꼬리 유연성 덕에 이기는 게 당연해서 실험이 죽는다.

**T-A 7.45 vs T-C(상자크기) 6.93. T-A 가 이긴 fold 0/7. 만장일치로 진다.**

- 분포족은 **실제로 도움이 됐다** — A 는 −2.03, C 는 −0.96 만큼 NLL 개선.
  t 가 A 를 두 배 더 도왔다. **그런데도 순위가 안 바뀐다**
- **자유도가 격자 바닥에 붙었다** — T-A 는 7 fold 전부 ν=1(코시). 적합이
  코시보다 더 두꺼운 꼬리를 원했다는 뜻이고, 그 최대 유연성으로도 진다

> **"가우시안 가정이 안 맞아서" 는 이제 변명이 안 된다.** 안 맞는 건 사실이고
> (꼬리비 12~213) 고쳐도(t, ν=1) 결론이 그대로다.

### 실험 1 계열이 닫혔다

| 물음 | 답 |
|---|---|
| σ 에 신호가 있는가 | **있다.** 편상관 0.32, 검출기·해상도 무관 |

| 그러면 상자크기를 이기는가 | **아니다.** 가우시안에서도 t 에서도 0/7 |

**남는 긴장 (정직한 미해결)**: 편상관은 0.32 인데 우도는 진다. 모순이 아니다 —
편상관은 **순위** 정보이고 우도는 **밀도 모형**이다. **σ 는 순위는 매기지만
모형으로는 쓸모없다.** 그리고 게이팅 통로(실험 3)에서도 σ 가 크기에 3.81 진다.

> **비용 통로와 게이팅 통로 양쪽에서 σ 가 단순한 크기 규칙에 진다.**
> 순위 상관 0.32 는 진짜지만, 쓸 수 있는 형태로 꺼내는 데 세 통로가 전부 실패했다.

(−0.096 nats). [1] 은 실패했다. 그리고 `[2]통과+[1]실패` 조합은 **사전 선언에

**판정 코드 버그 하나**: 짝 안 지은 두 목록의 중앙값을 비교하면 DFL 에서 부호가

### 이 판정이 논지에서 하는 일

이제 "검출 불확실성을 MOT 연관 비용에 쓰면 좋아지는가" 에 대해

**이건 실패가 아니라 결과다** — 다만 그렇게 쓰려면 표본(장면 7개)이 발목을 잡는다.

### 이어받는 지점 — 실험 5 의 2·3단계 (**완료됨. 기록용**)

1. **비용함수 + 자체시험** (미착수)
   - `W² = ‖ε‖² + tr(Σt + Σd − 2(Σt^½ Σd Σt^½)^½)`
   - **비싼 실행 전에 합성으로 검증할 것** (exp03 `selftest.py` 방식)
   - 함정 1: 갈래별 Σ 를 `E[tr Σ]` 로 규모 맞추기 — **안 맞추면 갈래 차이가
     정보가 아니라 규모가 된다**
   - 함정 2: Σt 는 칼만 P 로 고정 (갈래 무관 + 짝 일관성 원천 차단)
2. **트래커 재생 + HOTA** (미착수)
   - ultralytics BYTETracker 에 비용만 갈아끼운다 (exp00 `sweep.py` 수법)
   - HOTA 는 **UTrack 에 벤더링된 TrackEval** 사용
     (`external/UTrack/tracker/eval/collections/hota.py`)
   - **[0] 먼저**: 갈래 A(맨 IoU)가 exp02 기준선 **64.494 를 ±0.1 로 재현**해야
     한다. 안 되면 배관이 틀린 것이니 **판정하지 말 것**
3. **판정**: 주 종말점 `W-DFL − W-size`, 판정폭 0.3 HOTA

상세는 `experiments/exp05_wasserstein/README.md` (사전 선언 + **수학 감사**).

**2·3단계는 이미 만들어져 있다** (2026-08-17 저녁):
- `wcost.py` — 비용함수. 대각에서 Bures = sum(sqrt(st)-sqrt(sd))^2 로 떨어진다
- `selftest.py` — **8/8 PASS**. 공분산 역설 없음을 구현 수준에서 확인
- `replay.py` — 캐시된 검출을 BYTETracker 에 재생. `get_dists` 만 갈아끼운다.
  **관문 [0b](트랙 간 CV(Σt))를 여기서 잰다**

**전 과정 재현:**
```bash
python experiments/exp05_wasserstein/cache_detections.py   # 약 110분
python experiments/exp05_wasserstein/selftest.py           # 8/8 PASS
python experiments/exp05_wasserstein/replay.py iou w_dfl w_size
python experiments/exp05_wasserstein/accept_rate.py iou w_dfl w_size
python experiments/exp05_wasserstein/evaluate.py iou w_dfl w_size
```

**HOTA 배선에서 한 선택**: seqmap 적재 경로를 **안 썼다.** exp02 가 seqmap 헤더
누락으로 시퀀스를 하나 조용히 잃은 적이 있다. TrackEval 의 **지표 클래스만** 쓰고
적재는 직접 하되, **MOTChallenge 전처리(distractor 매칭 제거 → zero_marked/
pedestrian 필터 → id 재부여)를 소스 그대로 복제**했다. distractor 제거를 빼먹는
재구현이 흔하고 그러면 HOTA 가 몇 점씩 틀린다.

**수학 감사가 바꾼 것 둘** (결과 보기 전에 반영함):
- 관문 [0] 정정: exp02 의 64.494 는 UTrack `botsort` 값이라 ultralytics
  BYTETracker 로 재현 불가. 절대값 대신 **내적 타당성**으로 바꿨다
- 관문 [0b] 신설: Bures 의 비분리항은 Σt 가 트랙마다 달라야 산다.
  CV=0 이면 채널이 완전히 죽는다(합성 확인)

## 실험 6 — 임계값 레버. **세 번째 통로도 닫혔다** (2026-08-18)

실험 5b 에서 **채택률 보정만으로 HOTA 가 +7.14 움직였다.** exp00 도 "민감도의
원인은 임계값" 이라 했다. 그런데 그건 전부 와서스타인 갈래 얘기다.
**기준선(맨 IoU, `match_thresh=0.8`)에도 여유가 있는가**를 물었다.

### [A]·[B] 관문 — 여유는 전역엔 없고 장면별로만 있다

| | 물은 것 | 답 |
|---|---|---|
| **[A]** | 0.8 이 이미 꼭대기인가 | 전역 최적 0.85 는 **+0.037**. **ByteTrack 기본값이 이미 최적** |
| **[B]** | 꼭대기가 장면마다 다른가 | **다르다.** 0.70~0.98 로 갈리고 신탁 이득 평균 +1.49 |

**이득이 전부 "장면마다 다르다" 에 들어 있다.** 그래서 적응 규칙이 있어야 한다.

### 왜 이 자리를 팠나 — 눈금이 필요 없는 유일한 자리

임계값은 **장면당 스칼라 하나**다. 절대 눈금이 필요 없고 **단조 관계만** 있으면
된다. 그게 실험 1 이 확정한 σ 의 성질이다 — **신호 O**(편상관 0.32, 검출기·해상도
무관), **눈금 X**(χ² 80~562배). 지금까지 우리는 눈금이 필요한 자리(거리 exp05,
칼만 R exp02, 상자 확장 exp03)에 눈금이 틀린 양을 넣어 전부 졌다.

### 그리드를 고쳤다 — 라벨이 경계에 붙어 있었다

`headroom.py` 의 그리드는 상단이 0.95 였는데 **MOT17-10 과 -13 의 최적이 거기
붙어 있었다.** 경계에 붙은 argmax 는 라벨로 못 쓴다. 사전 선언에서 0.98 을
추가했고, **MOT17-13 이 0.95 → 0.98 로 옮겨가며 이득이 1.73 → 4.66 으로 커졌다.**
나머지 여섯은 그대로다. `predictors.py` 의 하드코딩도 정정했다.

> **그런데 MOT17-13 은 0.98 에서도 여전히 그리드 끝이다.** 진짜 최적은 밖에
> 있을 수 있다. 사전 선언한 그리드를 판정 도중에 늘리지 않았다 (철회 15번 교훈).

### LOSO 판정 — **[1] 실패. 레버 2 가 죽는다**

7 fold. 훈련 6개로 예측변수를 **fold 안에서** 고르고(사람이 안 고른다) 중앙값
이분 규칙을 적합해 본 적 없는 1개에 적용했다.

| 갈래 | 임계값을 어떻게 정하는가 | 결합 HOTA | 시퀀스 평균 |
|---|---|---|---|
| **R0** | 0.80 고정 (ByteTrack 기본값) | **61.002** | 56.737 |
| **R1** | 훈련 6개 최적값의 중앙값 (**장면 정보 0**) | 60.966 | 56.629 |
| **R2** | 훈련 6개로 적합한 **예측 규칙** | 60.795 | **56.986** |
| R3 | held-out 자신의 argmax (**신탁**) | 61.894 | 58.228 |

| # | 종말점 | 가중 결합 (주) | 가중 없음 | 판정 |
|---|---|---|---|---|
| **[1]** | **R2 − R0** | **−0.207** | +0.249 | **판정폭 안. 실패** |

| [4] | σ 계열이 뽑힌 fold | **3/7** | | σ/√area |

**부호가 가중 여부에 따라 뒤집힌다** (실험 5 와 같은 현상, 큰 시퀀스가 지배).
사전 선언한 주 판정은 가중 결합이고, **둘 다 판정폭 0.3 안이므로 결론은 같다.**
부호검정도 5/7, p=0.453 으로 미결이다.

> **신탁 회수율이 가중 −23%, 가중 없음 17% 다.** 규칙이 상한의 대부분을 못 가져온다.

### 이 판정에서 가장 중요한 두 줄

**첫째, 상한 자체가 작다.** 완벽한 신탁도 결합 기준 **+0.892 HOTA** 다.
설령 규칙이 신탁을 100% 회수해도 1점이 안 된다. **레버의 크기가 애초에 작았다.**

**둘째, R1 이 R0 보다 나쁘다** (60.966 vs 61.002). 장면을 안 보고 눈금만
옮기는 것도 도움이 안 된다. 즉 이득은 "0.80 이라는 숫자가 나빠서" 가 아니다.
**[A] 가 이미 말한 것과 같다 — ByteTrack 기본값이 이미 최적이다.**

### σ 는 골라지긴 했다 — 그런데 도움이 안 된다

**[4] σ/√area 가 3/7 fold 에서 뽑혔다.** 눈금이 필요 없는 자리에서 σ 는
후보로 선택될 만큼의 단조 신호를 갖는다. **그런데 [1] 이 실패했다.**

**선택이 불안정하다** (함정 (b) 대로): σ/√area 3, 상자 높이 중앙값 2,
자차운동 2 로 갈린다. 세 가지가 fold 마다 번갈아 뽑히는 규칙은 규칙이 아니다.

> **관찰 (사후, 주장 아님)**: σ/√area 가 뽑힌 3 fold(05·09·13)는 전부 R2 > R0
> 였고, 상자 높이가 뽑힌 MOT17-02 에서 **−3.52** 로 크게 졌다. **n=3 이고
> 사전 선언에 없다.** 다음 실험의 씨앗으로만 적는다.

### 이 판정이 논지에서 하는 일 — **세 의미론이 모두 소진됐다**

| 의미론 | 어떻게 | 실험 | 결과 |
|---|---|---|---|
| **게이팅** (σ 로 상자를 키운다) | 기하 확장 | exp03 | **−4.33 HOTA** |
| **유사도** (σ 를 거리에 넣는다) | 와서스타인 Bures | exp05 | **−1.08 / −10.56** |
| **임계값** (σ 로 장면마다 문턱을 옮긴다) | LOSO 적응 규칙 | **exp06** | **−0.21 (판정폭 안)** |

앞의 둘은 **눈금이 필요한** 자리였고 σ 의 눈금이 틀려서 졌다는 설명이 가능했다.
**exp06 은 눈금이 필요 없는 자리다.** 순위만 있으면 되는 곳에서도 이득이 없다.

> **"σ 의 눈금이 틀려서" 라는 변명이 여기서 끝난다.**

## 실험 9 — **분석 단위를 바꿔도 천장은 부분적으로만 열린다** (2026-08-18)

설계 계산(exp07)이 갈래 2 를 "유망하다" 고 적었다. **그게 정말 되는지 따졌다.**
사전 선언 `experiments/exp09_unit/PREREG.md` (커밋 `b9561c3`, 자료보다 먼저).

**이건 트래커가 아니라 설계에 대한 실험이다.** 물은 것:

```
Var(d_s) = Var_true(장면이 실제로 다르다) + Var_meas(재는 데 생긴 잡음)
```

`Var_meas` 가 지배적이면 결정 단위로 정밀하게 재서 천장이 열리고,
`Var_true` 가 지배적이면 **장면 수가 진짜 천장**이다.

### 관문 셋 통과

| 관문 | 결과 |
|---|---|
| **[0a]** Identity 전역 대응 복제 | 벤더링 구현과 IDF1 이 **1e-8 까지 일치** (7시퀀스) |
| **[0b]** 결정 단위 표본 | GT 검출 **53,890 건** (시퀀스당 2,879~24,178) |
| **[0c]** 갈래 간 단위 집합 | **완전 동일** |

### 결과 — 두 쌍이 갈리고, 갈리는 이유가 더 중요하다

**큰 효과 (`iou` vs `wn_size_rate`, 기록 HOTA −4.98)**

| 시퀀스 | 02 | 04 | **05** | 09 | 10 | 11 | **13** |
|---|---|---|---|---|---|---|---|
| IDTP 비율 차이 | +0.105 | +0.035 | **+0.205** | +0.053 | +0.021 | +0.100 | **−0.054** |

`Var_meas / Var(d_s) = 0.259` → 사전 선언표의 **"부분적"**

**작은 효과 (`th080` vs `th085`, 기록 HOTA +0.04)**

`Var_meas / Var(d_s) = 2.463` → **`Var_true` 가 음수다.**
사전 선언표로는 **"열린다"**.

### 그런데 그 판정을 그대로 믿으면 안 된다 — 스스로 만든 진단이 말린다

SE 추정 방식을 바꿔가며 주 종말점을 다시 냈다 (사전 선언이 "iid 값도 같이
적는다" 고 했다).

| SE 추정 | 큰 효과 몫 | 판정 | 작은 효과 몫 | 판정 |
|---|---|---|---|---|
| iid | 0.007 | 천장 | 0.108 | 부분적 |
| 블록 25 | 0.146 | 부분적 | 1.737 | 열린다 |
| **블록 50 (사전 선언)** | **0.257** | **부분적** | **2.498** | **열린다** |
| 블록 100 | 0.362 | 부분적 | 2.275 | 열린다 |

**시퀀스당 블록이 6~11개뿐이다.** 블록 6개짜리 부트스트랩 SE 는 불안정하고,
큰 효과 쪽에서 몫이 블록 길이를 따라 **단조 증가**한다(0.007 → 0.146 → 0.257
→ 0.362) — SE 추정이 아직 안정되지 않았다는 전형적 신호다.

### 그래서 무엇이 결론인가

**하나 — 큰 효과에서는 장면 간 차이가 진짜다.**
어떤 SE 방식을 써도 몫이 **0.36 을 안 넘는다.** 즉 `Var_true` 가 최소 64% 다.
MOT17-05 (+0.205) 와 MOT17-13 (−0.054) 은 어떤 SE 로도 못 메운다.
**장면이 실제로 다르다. 결정 단위로 쪼개도 이건 안 줄어든다.**

**둘 — 작은 효과에서는 가를 수 없다.**
관측된 장면 간 SD(0.00894)가 평균 블록 SE(0.01258)의 **0.71배**다. "전부 잡음"
과도, "약간의 이질성 + 과대추정된 SE" 와도 **둘 다 들어맞는다.**
표본 7개로는 그 둘이 안 갈린다.

> ### **"7개로 충분한가" 를 7개로 답할 수 없다**
>
> 이게 오늘 가장 날카로운 것이다. 분산 분해는 장면 간 산포를 두 조각으로
> 가르는데, **그 가르기 자체가 장면 수에 검정력을 의존한다.** 작은 효과에서
> `Var_true` 가 음수로 나온 것은 "이질성이 없다" 가 아니라
> **"7개로는 못 잰다"** 는 뜻이다.

**셋 — 실용적 결론은 그래도 분명하다.**
가장 낙관적인 몫(0.36)을 그대로 받아도 `Var_true` 가 전체의 64% 다.
필요 장면 수는 그 비율로 줄어드므로 **591 → 약 378.** 가용 자원은 57 이다.

> **자릿수가 안 바뀐다. exp07 의 결론이 그대로 선다.**
> (단 이건 IDTP 분산비를 HOTA 기반 n 에 옮긴 **시사**이지 재계산이 아니다.
>  종말점이 다르다.)

### 판정

**갈래 2 는 부분적으로만 열린다.** 결정 단위로 쪼개면 측정 잡음이 줄어
장면별 효과를 더 정밀하게 볼 수 있지만, **장면 간 이질성이 남고 그게 지배적이다.**
**군집이 7개면 일반화 추론의 자유도는 6 이고, 그건 n 을 53,890 으로 불려도
안 바뀐다** (사전 선언에서 미리 인정한 것).

### 이 실험이 남긴 부산물

## 실험 11 (E1) — **가산은 기여 0, 그런데 임계값으로 −3.75 를 낸다** (2026-08-18)

사전 선언 `experiments/exp11_add_vs_mul/PREREG.md` (커밋 `2ac0db4`, 자료보다 먼저).
원고 2절의 설계 제약을 합성(2e-16)에서 **실측**으로 옮겼다.

**설계**: 한 번의 재생 안에서 매 연관 호출마다 `base` / `add` / `mul` 세 비용을
만들고 **셋 다 푼다.** 트래커는 `base` 로 진행하므로 관측이 개입을 안 바꾼다.
섭동은 **일부러 크게** 줬다 — 가산의 기여 0 은 크기와 무관하기 때문이다.

**관문 통과**: 평균 `|Δcost|` = **0.177** (비용 범위 [0,1] 대비 크다), 두 갈래
섭동 크기 비 **1.00**, 연관 호출 **3,344건**. `N≤M` 이 **92.9%**.

### 결과

| # | 종말점 | 값 |
|---|---|---|
| **[1]** | `N≤M` 에서 `add` 의 임계값 전 할당 일치율 | **99.61%** |
| [2] | `N>M` 에서 같은 비율 | **75.42%** |
| [3] | `mul` 의 일치율 | **95.54%** (`N≤M` 만 96.69%) |
| **[4]** | `add` 의 임계값 **후** 채택쌍이 다른 호출 | **56.25%** |
| | (참고) `mul` 의 임계값 후가 다른 호출 | 29.64% |
| | HOTA | base 61.00, **add −3.75**, mul −1.01 |

### ⚠ [1] 이 100% 가 아니었다 — **명제가 아니라 내 조작화가 틀렸다**

사전 선언한 읽는 법은 *"[1] 이 100% 가 아니면 명제나 구현이 틀렸다"* 였다.
**판정하기 전에 원인을 갈랐다** (규칙 2). `diagnose.py`:

| 검사 | 결과 |
|---|---|
| `N≤M` 인데 할당이 달라진 호출 | **12건** |
| 그중 **동점** (`cost_add(P0) == cost_add(P1)`) | **12 / 12** |
| **진짜 위반** (`P1` 이 엄밀히 더 싸다) | **0 / 12** |
| 배정된 쌍 수가 다른 호출 | 0 / 12 |

차이가 **±3.6e-15** — 부동소수 잡음이다. **원래 할당도 여전히 최적**이고,
솔버가 섭동 뒤 **동점 중 다른 최적해**를 골랐을 뿐이다.

> **정리는 성립한다. 틀린 것은 내가 고른 종말점이다.**
> "솔버가 같은 집합을 돌려주는가" 가 아니라 **"최적성이 보존되는가"** 를
> 쟀어야 했다. 후자로는 **12/12, 즉 100%** 다.
>
> **사전 선언한 [1] = 99.61% 를 지우지 않는다.** 조작화 결함으로 기록한다.
> 원고에는 *"할당이 비트 단위로 같다"* 가 아니라
> **"최적성이 보존된다"** 로 쓴다.

### 이게 원래 주장보다 **강한** 결과다

가산은 할당에 **정보를 하나도 전달하지 않는데**(최적성 보존 12/12),
**임계값 통로로 호출의 56%에서 채택을 바꾸고 HOTA 를 −3.75 낸다.**

> **"불확실성을 더하면 중립적이다" 가 아니다. 기여는 0 인데 해롭기만 하다.**
> 곱은 할당 자체를 4.5% 바꾸고 손해가 −1.01 로 더 작다.
> **문헌이 예외 없이 곱을 쓰는 이유에 이제 측정된 근거가 있다.**

`N>M` 에서 75.42% 로 떨어지는 것은 **M,N 조건의 직접 확인**이다 —
열이 다 배정되지 않으면 열상수도 할당을 바꾼다.

### 정직하게 — 경쟁 설명 하나

> ### ⚠ **이 절은 감사 뒤에 뒤집혔다 (아래 「감사 정정」 참고).**
> 여지 값이 3단계 오염으로 과대추정돼 있었고, 고치니 **밀도가 1위에서 5위로
> 내려가고 연속 IoU 가 1위가 됐다.** 원문은 지우지 않는다.

**이건 지표 산물일 수 있다** — 물체가 적으면 ID switch 하나가 HOTA 에서

**n=7 상관으로는 카메라 운동과 밀도를 못 가른다.** 기제 측정(IoU<0.2 가

## 감사 정정 — **`get_dists` 는 두 번 불린다. 실험 셋이 그걸 몰랐다** (2026-08-18)

## 여지 +3.122 의 성분을 갈랐다 — **연관의 몫은 +2.352 (75.3%)** (2026-08-19)

원고 5.5 가 *"검출 캐시가 같은데 DetA 가 +1.233 오른다"* 는 우려를 **적어만 놓고
크기를 안 쟀다.** 잰다.

### 방법 — 알파별 정확 분해 (근사 아님)

`HOTA_a = sqrt(DetA_a * AssA_a)` 이고 TrackEval 이 알파별 배열을 그대로 준다.
성분을 갈아 끼운다:

| 조건 | HOTA | 기준선 대비 |
|---|---|---|
| 기준선 | 61.002 | |
| **AssA 만 오라클** | 63.354 | **+2.352** |
| 둘 다 오라클 | 64.124 | +3.122 |

**연관 정확도의 몫 75.3%, 출력 정화의 몫 24.7% (+0.770).**

사전 점검 둘을 스크립트 안에 뒀다 — (a) 기준선·오라클 HOTA 가 기록(61.002/64.124)과
맞는가, (b) `sqrt(DetA*AssA)` 재조립이 HOTA 와 일치하는가. 둘 다 통과해야 분해로 넘어간다.

### **+3.122 가 틀린 게 아니다**

완벽한 연관기를 넣으면 **실제로 +3.122 를 얻는다.** 출력이 정화되는 것도 연관이
좋아진 결과다. 다만 구성을 안 밝히면 *"연관 정확도만으로 3.1점"* 으로 읽힌다.

> 더 보수적인 **+2.352** 를 기준으로 삼아도 네 경로(−0.21 ~ −8.90)는 전부 그
> 아래다. **결론 불변, 상한만 보수적으로.**

이건 판정이 아니라 **이미 보고한 수치의 감도 분석**이다. 방향도 안전하다 —
연관의 몫은 +3.122 보다 작아질 수만 있다.

## 실험 17 — **합친 모형이 이긴다. 결론 2 를 고쳐야 한다** (2026-08-19)

심사 지적: 5.1 은 σ 가 **높이를 통제하고도** 정보를 가진다 하고(+0.322),
5.2 는 σ-만 모형이 높이-만 모형에 7/7 진다고 한다. 그러면 **둘을 합친 모형은?**
**한 번도 적합한 적이 없었다.** 사전 등록(커밋 `d2c1c4b`) 후 쟀다.

```
D  Sigma = k * h^2 * (s/median(s))^g      모수 (k, nu, g) -- C 보다 하나 많다
   g=0 이면 C 와 정확히 같다 (스크립트가 사전 점검으로 검산한다)
```

### 결과 — **소스에 따라 갈린다**

| 소스 | D 승 | 양측 p | 적합된 g | 차이 중앙 |
|---|---|---|---|---|
| **NMS 후보 분산** | **7/7** | **0.0156** | **+0.50** (7 fold 전부) | −0.012 nats |
| DFL 분포 분산 | 5/7 | 0.4531 | **−1.00 (격자 바닥)** | −0.024 nats |

전역 적합도 같다 (NMS 7/7, DFL 5/7).

**NMS 는 이긴다.** g=+0.50 이 7 fold 전부에서 같으므로 σ 를 실제로 쓴다.
**DFL 은 유의성 미달이고 g 가 음수 격자 바닥**이다 — σ 가 클수록 공분산을
*작게* 잡는 쪽이 낫다는 뜻이고, 이론과 반대이며 경계에 붙었으므로
**잡음이나 교란을 맞추고 있을 가능성이 크다.**

### 그런데 **효과가 작다** — 이게 핵심이다

| 비교 | 폭 |
|---|---|
| C 가 A 를 이긴 폭 (5.2 절의 주 결과) | **+0.560 nats** |
| D 가 C 를 이긴 폭 (이번) | **−0.012 nats** |

**47배 작다.** 즉:

> σ 는 **박스 크기를 대체할 수 없고**(0.560), 크기 위에 **아주 조금 얹힌다**(0.012).

### 원고 결론 2 를 고친다

~~*"NMS 후보 분산은 확률 모형으로 사용할 수 없다"*~~ 는 **너무 세다.**
정확히는 **"크기를 대체할 수 없다"** 이고, 합쳐 쓰면 7/7 로 유의하게 낫다.
다만 폭이 47배 작으므로 **실용적 함의는 거의 없다.**

**사전 등록에 미리 적어 둔 단서도 그대로 적는다** — 밀도 모형에서 이기는 것과

## 실험 20 — **사전 등록 가드가 내 버그를 잡았고, 내 논거도 틀렸다** (2026-08-20)

### 가드가 먼저 작동했다

기준 C 에서 NMS 가 `ALPHA 2000 -> 채택률 0.0112 (목표의 1.2%)` 로 포화했다.

### 그리고 예고했던 단조성 확인이 **내 논거를 반증했다**

보정 1 에 이렇게 적었다:

> ~~*"상자를 키우면 채택률이 오르므로(이 자료에서 단조) 기준선 채택률을 주는
> 해는 α≈0 하나뿐이다"*~~

**실측:**

| α | 0 | 0.25 | 0.5 | 1 | 5 | 20 | 100 |
|---|---|---|---|---|---|---|---|
| 크기 | 0.9633 | 0.9502 | 0.9170 | 0.3872 | 0.0027 | 0.0000 | 0.0000 |
| NMS | 0.9633 | 0.9627 | **0.9628** | 0.9621 | 0.9531 | 0.9015 | 0.7939 |
| DFL | 0.9633 | 0.9617 | 0.9604 | 0.9549 | 0.8625 | 0.0738 | 0.0002 |

**채택률은 α 에 오르지 않는다 — 내린다.** 검출 상자를 키우면 트랙 예측 상자와
크기가 안 맞아 IoU 가 **나빠지기** 때문이다. 그리고 **NMS 는 단조도 아니다**
(0.25 → 0.5 에서 0.9627 → 0.9628).

> **결론(기준선 맞춤의 해는 α≈0 뿐)은 살아남지만 논거가 반대였다.**
> 감소 함수라 기준선 값 0.9633 을 주는 점이 α=0 하나인 것이지,
> 증가해서가 아니다. **안 재고 적은 기제는 이렇게 틀린다.**

### 이분 탐색이 방향을 가정하고 있었다

`solve()` 가 `v > target -> hi = mid` 로 **증가 함수를 가정**했다. 감소 함수에서는
반대로 몰려 상한으로 달아난다. **첫 판의 포화가 이것이다.**
`inc = measure(hi) > measure(lo)` 로 방향을 자동 판정하게 고치고 다시 돌린다.

### 순서를 밝힌다

기준 A·B 의 값을 **보고 나서** 이 버그를 고쳤다. 다만 [1]·[2] 의 읽는 법과
분모 규칙은 자료 전에 박혀 있고 **하나도 바꾸지 않았다.** 고친 것은
사전 등록한 절차(*"이분 탐색으로 target 에 맞춘다"*)를 **실행하지 못하게 하던
구현 버그**다. 그 구분을 여기 적어 둔다.

## 기제가 갈렸다 — **쌍 어긋남이다. 꼬리가 아니다** (2026-08-20)

심사가 경쟁 가설을 냈다. 사전 등록한 가르는 실험을 돌렸다 — 게이팅에서
트랙을 **그 쌍의 검출 σ** 로 키워 어긋남을 **구성상 0** 으로 만든다.

| 소스 | α=0 | α=16 (기존, 트랙 자기 σ) | α=16 (**쌍별 σ**) | |
|---|---|---|---|---|
| **NMS** | 0.963280 | **0.955115** ↓ | **0.970181** | **↑ 기준선 위** |
| DFL | 0.963280 | 0.975731 ↑ | 0.981937 | ↑ 더 오른다 |

**어긋남을 없애니 NMS 가 기준선 위로 돌아선다.** 사전 등록한 읽는 법대로
**(가) 쌍 어긋남**이 지지되고 **(나) 두꺼운 꼬리는 기각**된다.

### 사정거리 — **좁은 쪽으로 한정된다**

사전 등록에 미리 적어 둔 대로:

> *"NMS 가 ↑ 로 돌아선다 → (가) 쌍 어긋남이다. 주장을 **'양쪽 확장에는 쓸 수
> 없다'** 까지로 한정한다. **단측 확장에 전이하지 않는다.**"*

즉 **UncertaintyTrack 의 2차 통과 단측 확장에는 이 결과가 전이되지 않는다.**
꼬리였다면 확장 기반 전부에 걸리는 훨씬 강한 결과였을 텐데 그쪽이 아니다.
**안 가르고 넓은 쪽을 썼으면 규칙 7 위반이었다.**

### 곁가지 — 왜 NMS 만 걸리나

측정한 변동성이 설명한다 (트랙 116개, `median |Δlog σ|`):

| 소스 | 중앙값 | 90분위 |
|---|---|---|
| **NMS** | **0.1617** | **1.5499** |
| DFL | 0.0198 | 0.2157 |
| size | 0.0057 | 0.0571 |

NMS 는 DFL 보다 **8배** 변동한다. 트랙과 검출이 같은 프레임 값이어도 서로 다른
튀는 값이라 pad 가 어긋나고, **변동이 클수록 어긋남이 크다.** 크기는 트랙 상자에서
매번 계산되므로 애초에 어긋날 것이 없다.

### 격자 논증의 형태 — 사전 등록대로

**NMS 게이팅 칸은 "졌다" 가 아니라 "개입 불성립" 으로 적는다.**
확장이 문을 여는 방향으로 작동하지 않는 조건에서 나온 ΔHOTA 는 소스가 진
근거가 아니다. 따라서 §7.1 셋째의 **"여섯 칸이 모두 음수" 라는 표현을 쓰지 않는다** —
**다섯 칸 + 개입 불성립 한 칸**이다.

### 정정 — **가르는 실험이 가르지 못했다** (2026-08-20)

바로 위에서 *"(나) 두꺼운 꼬리는 기각된다"* 고 적었다. **틀렸다.**

**쌍별 σ 는 두 상자에 *같은* pad 를 붙인다.** 그러면 σ 가 아무리 큰 값이어도
두 상자가 **함께** 부풀어 IoU 가 오히려 1 로 간다 — **꼬리의 손해 통로도 같이
사라진다.** 즉 이 설계는 어긋남과 꼬리를 **둘 다** 제거하므로,
**NMS 가 ↑ 로 돌아선 것은 두 가설 어느 쪽에서도 예측된다.**

그리고 우리가 잰 변동성 표가 **꼬리를 확인해 준다** (90분위/중앙값):

| 소스 | 중앙값 | 90분위 | 비율 |
|---|---|---|---|
| **NMS** | 0.1617 | 1.5499 | **9.6배** |
| DFL | 0.0198 | 0.2157 | 10.9배 |
| size | 0.0057 | 0.0571 | 10.0배 |

가우시안이면 이 비율이 약 2.5 다. **셋 다 시간축에서 두껍고, NMS 는 절대 크기가
DFL 의 8배다.**

> **꼬리와 어긋남은 대안이 아니라 원인과 통로다.**
> 정확한 문장: **"손해는 pad 비대칭을 통해 들어오고, NMS 에서 비대칭이 큰 이유는
> σ 의 프레임 간 변동이 두꺼운 꼬리를 갖기 때문이다."**

**"꼬리는 기각됐다" 를 쓰지 않는다** — 그 문장은 **단측 확장이 안전하다**는 뜻을
품는데 이 실험은 단측에 대해 아무것도 안 쟀다.
**단측에 전이하지 않는다는 한정은 그대로 옳고, 오히려 이 이유로 더 옳다.**

### 표기 고정 — **0.970181 은 채택률이지 HOTA 가 아니다**

위 표의 `↑ 기준선 위` 가 나중에 *"NMS 가 이겼다"* 로 미끄러지기 쉽다.
**채택률이 오른 것은 문이 더 열렸다는 뜻이지 추적이 나아졌다는 뜻이 아니다.**
**방향 검사 통과이지 결과가 아니다.**

### 묻어 두지 않는다 — §7.4 에 한 줄

**쌍별 σ 는 이 프로젝트에서 게이팅의 문을 연 유일한 구성이다.**
사전 등록 안 한 조건이므로 격자에 넣지 않는다. 다만
**실패가 신호의 문제가 아니라 형식의 문제일 수 있다**는 쪽을 가리키므로
향후 과제에 남긴다 — **채택률만 봤고 HOTA 는 안 쟀다**는 단서와 함께.

### 재정정 — **꼬리를 원인 자리로 옮긴 것도 틀렸다** (2026-08-20)

*"꼬리 기각"* 을 철회하면서 **꼬리를 원인 자리로 옮겼는데, 같은 표가 그것도
막는다.**

| 소스 | 중앙값 | 90분위 | **비율(모양)** |
|---|---|---|---|
| NMS | **0.1617** | 1.5499 | **9.6** |
| DFL | 0.0198 | 0.2157 | **10.9** |
| size | 0.0057 | 0.0571 | 10.0 |

**비율로는 NMS 가 셋 중 제일 가볍다.** 가우시안 2.5 대비 셋 다 4배쯤 두꺼우니
**꼬리 모양은 세 소스의 공통 성질**이고, 꼬리가 원인이라면 비율이 더 높은 DFL 이
최소한 NMS 만큼 나빠야 하는데 **DFL 은 ↑ 다.**

**NMS 를 가르는 것은 모양이 아니라 크기다** — 중앙값이 DFL 의 **8.2배**,
박스 크기의 **28.4배**.

> **최종 문장 (이걸 쓴다):**
> **"손해는 pad 비대칭을 통해 들어오고, NMS 에서 비대칭이 큰 이유는 σ 의
> 프레임 간 변동 *크기* 가 DFL 의 8배·박스 크기의 28배이기 때문이다.
> 꼬리 *모양* (90분위/중앙값 ≈ 10)은 세 소스에 공통이므로 NMS 를 가르지 않는다."**

**단측 비전이 한정은 이 정정과 무관하게 옳다** — 근거가 *"단측을 안 쟀다"* 이기
때문이다.

### 여기서 멈춘다

기제를 더 가르려면 잣대를 또 만들어야 한다 (예: DFL 의 σ 에 NMS 수준의 프레임 간
흔들림을 주입해 ↓ 로 뒤집히는지). **그건 향후 과제다.**
좁힌 주장(*"NMS σ 는 양쪽 확장에 쓸 수 없다"*)은 **이미 직접 측정된 것**이고,
기제 문장은 **설명이지 근거가 아니다.**

그건 이미 확인된 사실이기 때문이다.

### 정정 — **"꼬리가 없어서 무효" 는 꼬리를 기제로 되세운 것이다** (2026-08-20)

바로 위에서 이렇게 적었다:

> ~~*"합성에는 그 꼬리가 아예 없다. 그러니 이 탐침이 '열린다' 고 해도
> exp19 를 무너뜨린 바로 그 통로를 안 건드린 것이다."*~~

**틀렸다. 세 커밋 전에 내가 고정한 기준과 어긋난다.**

`964d456` 이 박은 문장: **가르는 것은 꼬리 *모양* 이 아니라 변동의 *크기* 다.**

그 기준을 탐침에 적용하면 결론이 뒤집힌다:

| | **중앙값(크기)** | 비율(모양) |
|---|---|---|
| 합성 | **0.2578** | 2.38 |
| 실제 NMS | 0.1617 | 9.6 |

**합성이 중앙값 비대칭이 1.59 배 크다.** 가르는 것이 크기라면 합성은 실제보다
**더 가혹한** 조건이고, 그런데도 열렸다면 탐침은 **보수적**인 것이지 무효가 아니다.
*"꼬리가 없어서 무효"* 라고 쓰는 순간 **꼬리를 다시 기제 자리에 세운다** —
사흘 전 철회한 바로 그 자리다.

그리고 그 문장은 **안 잰 것을 전제한다** (규칙 7) — *"붕괴는 꼬리에서 온다"* 를
재지 않고 썼다. 실제로는 어느 분위수가 붕괴를 만드는지 측정한 적이 없다.

### 세울 수 없는 이유는 **꼬리가 필요 없다**

- **(가)** 합성 장면은 실데이터가 아니다
- **(나)** 두 파이프라인이 **다섯 군데** 갈린다 (모서리 σ 공식, CAP, σ 출처,
  추적기, 기준선 64.494 대 61.002)
- **(다)** 필요조건 검사는 **통과해도 아무것도 확정하지 않는다**

**꼬리 차이(2.38 대 9.6)는 기제가 아니라 (나) 에 더해지는 여섯 번째 차이 한 줄이다.**

### 탐침의 양성 결과도 **함께** 적는다

한계를 *"검증 구간이 5 배 다르다"* 로만 쓰면 **실제보다 나쁘게 읽힌다.**
`both` 가 α=40 까지 단조로 문을 연 것(0.460 -> 0.246)은 **약하지만 통과한 검사**다.
범위를 붙여 함께 적는다 — *"합성 장면에서는 본 실행 구간까지 열렸으나
실데이터에서 확인한 것은 아니다."*

### `det` 재현은 탐침의 가장 단단한 산출물이다

게이트 2.21% -> 0.05% 단조 폐쇄. **다른 파이프라인, 다른 잣대, 같은 결론** —
규칙 3 이 요구하는 곱셈 대조다. 철회 17 이 exp03 자기 수학 안에서 재현된다.

**판정은 안 바뀐다 — 여전히 미결이고 −4.33 도 88% 도 안 건드린다.**
바뀌는 것은 **이유 한 줄**이다.

## 관문이 잡았다 — **재생이 다른 IoU 를 쓰고 있었다** (2026-08-20)

Colab 에서 추적 7 개를 다 돌리고 덤프(7,314 호출)를 얻은 뒤, 재생 단계에서
관문이 걸렸다:

```
[관문] cython IoU 대 numpy IoU  max|diff| = 2.632e-02  !! 어긋난다 -- 멈춘다
```

**부동소수점 잡음이 아니라 다른 함수다.** UTrack 의 `ious` 는
`fuzzy_cython_bbox.bbox_overlaps` 이고 Faster R-CNN 계열의 **+1 픽셀 규약**을
쓴다. 재현해 보니 전형적 보행자 상자에서 `max|diff| = 2.0e-02` — 같은 크기다.

### 원인은 **조용한 대체**다

`box_relax.py` 의 `_get_ious()`:

```python
try:
    from .matching import ious      # 패키지 안 -> cython (+1 규약)
except (ImportError, ValueError):
    return _numpy_ious              # 패키지 밖 -> numpy (+1 없음)
```

**최상위로 임포트하면 말없이 다른 함수가 된다.** CLAUDE.md 가 적어 둔
*"가로챈 뒤에도 변환이 남아 있는지 확인한다"* 의 자리다.

### **곁가지가 더 크다 — exp03 의 자체 시험이 쓰는 경로가 본 실행과 다르다**

`selftest.py` 의 `load()` 가 최상위로 임포트한다. 그러므로:

- `[1] measure vs plain IoU  max|diff| = 0.000e+00` 은 **numpy 대 numpy** 였다.
  본 실행이 쓰는 cython 경로는 **한 번도 시험된 적이 없다**
- 오늘 돌린 합성 탐침 `[S]` 도 numpy IoU 위에서 돌았다

`[S]` 의 방향 결론(양쪽 확장이 문을 연다)은 **같은 함수를 α 전체에 일관되게
썼으므로** 그 자체로는 유효하다. 다만 **"합성이라 못 세운다" 는 이유 목록에
여섯 번째가 아니라 일곱 번째가 붙는다 — IoU 함수마저 본 실행과 다르다.**

### 고친 것

- `direction.py` 가 `tracker.box_relax` 로 임포트한다 (패키지 안). 재생이
  `mod._get_ious()` 를 쓰므로 **본 실행과 같은 IoU** 다
- **관문을 값 비교에서 객체 동일성으로 바꿨다.** 값 비교는 *"얼마나 다르면
  통과인가"* 라는 자유도를 남기는데 여기서 옳은 답은 **같은 함수** 하나뿐이다
- `run_colab.py` 의 `stage_direction` 이 `UTRACK_ROOT`/`PYTHONPATH` 를 넘긴다
  (안 넘긴 것이 내 버그였다)
- 가짜 UTrack 패키지(+1 규약 `ious` 포함)로 **끝까지 돌려 확인**했다

### 환경 문제 셋 (런북에 넣을 것)

|---|---|

## exp03 방향 측정 — **중립이다. 그리고 단조가 아니다** (2026-08-20)

### 판정 — 사전 등록한 세 갈래 중 **중립**

α=10 에서 채택 쌍 변화가 **정확히 +0**, 문턱 5 쌍 안이다. 대칭차가
884 건(**1.92% ≥ 1%**) 이므로 사전 등록한 읽는 법대로:

> **개입은 돌았고 방향이 중립이다. `−4.33` 은 유효하되
> "문을 여는 개입" 이라는 서술은 못 쓴다.**

**심사가 만들라고 한 갈래가 정확히 이 경우였다** — *"채택 수가 안 변했다고
개입이 안 돈 게 아니다. 개수는 같은데 어느 쌍이 채택되는지가 다 바뀔 수 있다."*
개수만 봤으면 *"개입이 안 돌았다"* 로 잘못 갈 뻔했다.

### **단조가 아니다 — 보정 2 의 (6) 이 반증됐다**

*"이 자료에서 단조"* 라고 적었는데 **뒤집힌 U 자**다. α=5 까지 오르다
α=10 에서 기준선으로 돌아오고 그 뒤로 떨어진다. **α=10 은 전환점 위에 있다.**

**따라 나오는 것**: 보정 1 의 (1) 이 *"단조이므로 기준선 채택률을 주는 해는
α≈0 하나뿐 → 게이팅에서 기준선 맞춤은 원리적으로 불가능"* 이라고 했는데,
**α≈10 이 두 번째 해다.** 그 논거는 틀렸다. 다시 써야 한다.

### pad 비대칭 — **90분위를 그대로 읽으면 안 된다**

읽을 수 있는 것은 **중앙값 0.6395** 이고, 합성의 **2.6 배**다.
**실제 σ 의 쌍별 어긋남이 합성보다 훨씬 크다** — 합성 탐침이 왜 못 세우는지의
